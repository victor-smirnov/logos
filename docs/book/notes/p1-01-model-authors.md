## Positions already stated (seeded from session memory, 2026-10-10)

- 2026-10-10: "Пока мы делали Logos, ручное программирование потеряло смысл." Logos is a language for model authors. Motivation: models write well in low-resource languages; their code is locally better than human code (compiler-generated SSE vs hand asm analogy); models take tasks of a complexity humans no longer take on economically and need more powerful languages than ones built for a human at a workstation.
- 2026-10-10: humans still read and write code in far OOD (where models are out of distribution); in InD and near OOD hand work no longer pays. Review goes through models; only critical code (payments, security) gets manual verification on top of formal verification. Large code volumes are hard to understand in any syntax, so "readable syntax" does not rescue human comprehension at scale.
- 2026-06-27 (superseded 10-10): Logos was not to be framed as AI-first; LLM-fit "coincidental". Still true from then: the Rust-like surface was chosen by the model during design.
- 2026-07-13: the compiler is a sensor for a model, not an obstacle. A rejection is a cheap external falsification signal. Humans take rejection personally, and that tolerance ceiling shaped the industry (dynamic languages, error-message diplomacy, gradual typing). Models lack it constitutively; their avoidance behaviours are mimicry, correctable by harness. Consequence: checkers may be stricter than any human population would accept; verification density is a productivity multiplier.
- 2026-08-06: dynamic Logos rejected. Reasons: the stack bets on static derivability (plans, justification derived); strictness is the sensor; a second semantics is a span-killer. Interactivity = compile speed (REPL + incremental JIT); runtime-shaped data = Writ documents; ad-hoc queries = Deem; one boundary dynamic type over Writ.
- 2026-08-11: Rust 1.93 was a starting base, never a compatibility target. Rust's disease: enumerations of "but-if" reasons on a prematurely stabilised base instead of derivation. Direction: re-derive from a small logical core, spec in Deem, semantics simplified, syntax nearly kept.
- 2026-07-11: Rust semantics = surface profile kept for model fluency; semantic core = judgements over a registry of reasoners. "A noticeable part of rustc simulates a missing reasoner" (query system, trait solver, Polonius), as half of C++ Memoria simulated metaprogramming.
- 2026-07-10 (ADR 0018): "Logos IS Memoria in the form of a programming language."
- 2026-10-10 (ADR 0032): Logos Core = Rust + Deem + Writ + Hest; Memoria and Canon periphery. Human reads intent: declarations, plans, justifications, specifications.
- 2026-10-10: every "practical task" sits on a relational-graph model; tasks that do not fit are rare and get rarer on non-coherent hardware. Coherent multithreading stays in Rust-core; without coherence, distributed Datalog (CALM).

## Primary source: blog series "Code in the AI-Primary Era" (logos-site/content/blog, 2026-07-06..14, ≈20 k words)

Claims per part, compressed; the chapter states them in the book register and cites the posts.

1. Your Language Has Two Users Now (07-06). Model = author (generation over densely seen material; weak at executing deterministic procedures); human = owner (judgment, invariants, accountability; needs operational closeness). Logos: C++-level depth for the model (structured const generics, type packs, metafunctions), Rust-like skin for the human. "Premature passivisation": rationing expressive power to protect a user who no longer writes. Ownership dial (sign&ship ... re-verify everything), per task. Verification cheaper than search (NP analogy). Responsibility without control = scapegoat. Claim: better models ⇒ MORE classical deterministic code (checkers, gates), not less.
2. A Model Is Not a Calculator (07-08). Compressibility axis: no short generator (translation, idiom) ⇒ scale wins; short deterministic generator exists (arithmetic, type checking, query planning) ⇒ model approximates, scale does not close it. Error physics: left side damps errors, right side amplifies them. Wirth: data = incompressible term, algorithms = compressible; NN superposes both in one tensor. Approximate execution, bimodal failure profile, no internal regime signal. Rule 1: deterministic work offloaded to symbolic algorithms (reproducibility + verifiability). Rule 2: periodic offloadable work offloaded asymptotically (economics). Third role: guardrails/trajectory confinement. Deterministic components: compute, cache, constrain.
3. Attraction Basins (07-10). X_{n+1}=F(X_n); termination learned; limit cycles; object of study = basin. InD support fragmented: archipelago. Confidence = basin membership, not correctness. Low inventiveness. Steering vs forcing (open water). Three geometries (model wide/soft, human narrow/sharp, symbolic degenerate) must interlock; diagnostic = boundary object; convergence rate is a platform variable.
4. The Model Cannot List What It Knows (07-12). Point-query engine: no inversion, no enumeration. OOD gap (never learned) vs InD gap (known, not emitted); externally indistinguishable until probed. Generation ≠ verification. Self-written tests inherit blind spots; self-review does not surface InD gaps. Sampling to enumerate costs ~1/ε per tail item. Enumeration of self is a reflexive operation, not offloadable. "The list must come from outside."
5. The Failure Mode Humans Don't Have (07-14). Humans share the failure modes; the substrates differ, so blind spots are drawn from different distributions (weakly correlated error = amplification). Uniform shallow gaps: local-syntactic competence vs global-semantic correctness; joint satisfaction decays as p^N. External corpus = the materialized extent the model lacks (rustc/core/alloc/std tests). Discovery dynamics: constant rate = sampling not draining; depth falls; false summit. Instance coverage ≠ class coverage; generalizing pass with sibling cases. Model = proposal distribution; gap ledger; Writ as navigable store.
6. One System, One Dynamics (07-10). Mutual steering; one asymmetry: only the human carries responsibility (legal fact; Synthea). Responsibility requires comprehension the platform must supply. Throughput bounded by the rate a human can responsibly own output. Ownership spectrum direct ↔ mediated; ceiling of mediated ownership raised by serving the model. Human = binding constraint; model of human performance missing; engaged human not fungible. Two platform goals: G1 minimise cost of offloading to deterministic components; G2 structured reward signal (diagnostics as data, causal structure, observable state).
7. Attention Is the Budget (07-10). Ownership acquisition split from writing; comprehension phase squeezed under deadlines; attention does not scale or parallelise; productivity number is an open empirical question.
8. Worse Is Better Was a Law of the Carrier (07-14). Design propagates iff C < B (coherence complexity vs carrier bandwidth); human B constant 50 years; model B rising. Corpus strata: descriptive (what was built) vs normative (literature of regret); principles compress, hacks are memorised. Conditioning moves the mode; a model cannot condition itself (martingale, E[p(·|own sample)] = p(·)). Reasoning extends reach within a connected component (island); crossing needs conditioning, training, or verified improbable steps; per-step error ⇒ ~1/ε unverified steps. Greenfield is OOD. Predictions: unlock in coherence order; quality decouples from team size; coherent systems more productive for models.
9. The Compiler Is a Sensor (07-14). Strictness ceiling was emotional; rejection = cheap external falsification; model avoidance is mimicry (removable). Explicitness dividend: magic trades reader for writer; model pays verbosity in tokens; implicit constructs are context-non-local. Logos/Memoria strictness past human tolerance (view invalidation over packed structures; zero escape hatches in low-level subsystems). Verification density = productivity multiplier.
10. The Phase Transition (07-14). Observation: capability on a project jumps when the declarative stratum crosses a threshold (seen across projects and models). Mechanism: models reason natively over declarative material; coherent systems compress (model holds the generator); (1-ε)^N across seams. Capability radius = conditional compression complexity C_M(target | foundations + context). Ratchet: step past the known, verify, consolidate, repeat. Radius ∝ model strength × chain length through memory × verification density. Flywheel on coherent substrate; painkiller productivity on legacy. Falsifiable protocol: verified outcome per token on two stacks; three predictions. Benchmark does not exist yet.

## Primary source: site docs (logos-site/content/docs/introduction.md, roadmap.md; index.md)

- Introduction, the problem: three pressures. (1) code and data grow without bound, AI multiplies both (GitHub COO: ~275 M commits/week, ~14 B in 2026, latent.space); models do not execute, so computation moves into symbolic code: more code over more data. (2) more software IS a database (in-memory graphs, indexes, caches, consistency rules). (3) no language is built for this; C/C++/Rust leave data structures, schemas, queries to libraries.
- Logos = DB-first, AI-first. Origin: Memoria (C++), two walls: TMP does not scale (Rust worse within the same bounds); safe code not practically achievable (verification needs a type system stronger than memory safety). Rust's type-level metaprogramming reached C++ parity too late.
- Why now: AI lowers both halves of a language's fixed cost, building and adopting; a niche that could not justify a language can now.
- AI-first at three levels: language (strong expressive types = what models generate well and what verification bites on); tools (compiler = reward signal; types, diagnostics, executable test corpus, verification); paradigm (models author rules well, execute long exact derivations badly; deduction is calculation over another algebra; Deem = declarative plane = offload target for reasoning). Cited evidence: arXiv 2502.01100 (logic benchmarks, inference-time scaling does not lift the curse of complexity); arXiv 2502.15776 (formalize-then-solve: +65 points absolute). Declarative plane pays in feedback quality: every conclusion carries its justification; reward signal vs error code.
- The bet: as models write most code, languages compete on the quality of feedback to the model; winners strong in both components, imperative and declarative.
- Compilers are already databases: rustc query system ("database"), Salsa, Clang AST Matchers. Logos dogfoods: Writ = AST/IR format; Trama formats text in metaprograms; Deem slated for AST/IR analysis; Hest/LCM = compiler's dataflow target.
- Relationship to Rust: surface chosen with the model in mind (models generate Rust reliably; good DSL host). Today tracks Rust 1.93: deviation = bug unless blessed. Compatibility not a goal, divergence not a goal; diverge where AI-first or DB-first need pushes. Planned: capabilities in the type system; memory semantics reworked for Hest/LCM.
- Roadmap: 1.0 = self-hosted data platform whose compiler is one of its applications. "Logos is not Rust 2.0"; Rust = bootstrap language. Semantics of the language = continuation of the semantics of its base reasoners; constructs surface what engines can soundly derive. Platform = service: CLI, LSP, MCP over one incremental fact-base engine; MCP = model projection (query facts, ask why, what-if forks, standing queries). Self-hosted except codegen (C++ over MLIR/LLVM). Language design derived from reasoners; spec generated (already extraction-based, evidence links). "No human bottleneck this time": language-over-Datalog platforms failed at human authoring capacity; models write wide regular declarative code better. Stages 1-5 (harden data platform with Memoria→Nous cascade; self-hosted; cross + seed; builds; 1.0 C++ compiler retires). Divergence with a purpose: Rust's design shaped by NOT having a resident reasoner (coherence, specialization, repeated bounds, const exprs). Signature divergence candidate: capability discipline (runtime ocap + derived static effects). Beyond 1.0: conservative extension gate; Logos 2.0 may never exist.

These answer chat questions 1 (Rust = bootstrap language and current oracle, not destination) and 2 (centre = DB-first + AI-first; 1.0 = data platform whose compiler is an application) unless Victor revises them.

## Discussion

- 2026-10-10 (Victor): chapter subject = what a language for models (AI) must be. LLMs have a different cognitive ergonomics, and a different in-distribution than a human (a human has not seen nearly as much). The blog series develops the problem. Material is bleeding edge: publications may be hard to find.
- 2026-10-10 (Victor), "different in-distribution" = literally a different training dataset. For a human, embodiment plays a huge role, and a human learns through interactive interaction with the environment. Models memorise large volumes of DESCRIPTIONS of agents' interactions with environments and generalise over those descriptions.
- 2026-10-10 (Claude, derived, to confirm with Victor): consequences for a language. (a) Model InD = what is well described in text; tacit knowledge (undocumented conventions, tribal practice) is OOD for the model, heavily described material (Rust semantics, SQL, Datalog literature) is InD; hence a language for models must be DESCRIBED: semantics stated explicitly (spec, ADR, justification as data), which is the declarative stratum of the phase-transition post. (b) The model learned from descriptions of other people running code, not from running it; the interactive loop absent at training is supplied at inference: compiler, tests, REPL, oracles are the model's environment, a substitute for embodiment; "compiler as sensor" read literally. (c) Interface metaphors grounded in embodied cognition (visual layout, colour, spatial memory) carry little for the model (blog G2). (d) Descriptions span all traditions at once, so their combination is InD for the model and for no human team. Caveat to settle (asked 10-10, open): post-training of current models includes RL in execution environments (interactive, verifiable reward), small in volume relative to pretraining.
- 2026-10-10 (Victor): define near-OOD explicitly: OOD that is PRACTICALLY reachable from InD through the model's reasoning ("derivable" OOD). far-OOD = everything else.
- 2026-10-10 (Claude, proposed formalisation, to confirm): InD = support of the training distribution (descriptions). near-OOD(M, F, V, B) = targets t outside InD with a derivation from InD plus loaded foundations F, each step in-distribution for M, whose length fits the budget B and the decay bound: unverified chains survive ~1/ε steps, verified rungs (verifier V) reset the error. Measure: C_M(t | F + context) (blog part 10). far-OOD = the rest; crossing needs new information in context (conditioning), training, or an improbable step kept by an external verifier (selection). The boundary is relative: loading foundations, adding verifiers, and consolidating verified results (ratchet) move targets from far-OOD into near-OOD. Human role per 10-10 memory: humans work mainly in far-OOD; review of InD and near-OOD goes through models.
- 2026-10-10 (Victor): near-OOD grows as models' reasoning ability grows. It is also widened by offloading: reasoning can be moved to a symbolic reasoner, which has substantially greater capacity for qualitative (sound) reasoning.
- 2026-10-10 (Claude, derived, to confirm): offload widens near-OOD on both limits. Metric: a reasoner's steps have ε = 0, so chain length is bounded by compute, not by 1/ε (a fixpoint runs millions of steps). Topological: the reasoner has no probability bias, so it takes steps the model finds improbable as long as they are valid; the island limit of model-only reasoning does not apply to the derived part. The model's share shrinks to formalisation (state facts, rules, specs) and interpretation of the result; both must be InD or near-OOD for the model, hence the reasoner's input language must be well described (Datalog, SMT-LIB, Lean are) and its output (derivations, justifications) must be readable back as data. Proposed parameters: near-OOD(M, S, F, B), with S = the symbolic components available (verifiers check steps, reasoners produce them). Link to Logos: the language embeds reasoners (Deem, the Datalog borrow checker; SMT and Lean in Part VII), so working in Logos widens the model's near-OOD; roadmap's "semantics = continuation of the base reasoners" is the same statement seen from the language side. Evidence: arXiv 2502.15776 (formalize-then-solve +65 points), Idris 22→54/56 with compiler feedback, vericoding 68→96 %.
- 2026-10-10 (Victor), on "humans work mainly in far-OOD": viewed as a distribution, the human is complementary to the model's own distribution. Through language the two distributions can condition each other mutually.
- 2026-10-10 (Claude, derived, to confirm): H (human) and M (model) have supports built from different data (embodied interactive experience vs textual descriptions); they overlap on the shared textual culture and diverge elsewhere, so the model's far-OOD is partly the human's InD and vice versa. Conditioning: human text (prompt, constraint, spec, ADR, review) is an information source outside M, so it supplies the drift M cannot produce by self-conditioning (blog part 8, E[p(·|own sample)] = p(·)); model output (proposals, explanations, derivations) conditions H the same way (blog part 6, mutual steering). Weakly correlated errors (blog part 5) are the same fact seen from failure. Language is the channel; Logos is a formal part of that channel: declarations, specs, plans and justifications are conditioning text with checkable semantics, read by both. Design requirement: the language must condition well in both directions: precise for M, readable as intent for H (Rust skin, intent-level declarations). Open: "complementary" in the strict sense (disjoint supports) or "largely non-overlapping beyond the shared textual culture".
- 2026-10-10 (Victor) RESOLVED: "complementary" = largely non-overlapping beyond the shared textual culture, not disjoint supports; no strict estimates exist yet (state it as qualitative). Verifiers and reasoners are ONE S: "it is the same offload". Definition stands as near-OOD(M, S, F, B).
- 2026-10-10 (Victor), cognitive ergonomics: our (humans') biggest problem is that models exceed us by orders of magnitude (1000+×) in "understanding", the capacity to process information. Visible already: working with AI puts a huge cognitive load on the human; we cannot keep up. In programming AI writes decent, not ideal, code. The complaint ("neuroslop") is that it does not fit human perception: too much of it, different, unfamiliar, structured differently. Models can write human-fit code when asked, but the volume still overwhelms. Worst of all: models write very effectively in languages that are "too complex" for the average programmer and therefore unused in commercial programming. Now they WILL be used.
- 2026-10-10 (Claude, derived, to confirm): (a) the asymmetry is the central ergonomic property; the others (large flat context, near-zero cost of verbosity, no fatigue, no ego) are its components or corollaries. Lower-bound illustration of the throughput gap: adult silent reading ≈ 238 wpm for non-fiction (Brysbaert 2019, J. Memory and Language, meta-analysis) ≈ 5 tokens/s; model prefill runs thousands of tokens/s; the 1000× figure covers more than throughput and stays Victor's estimate. (b) The complexity budget of the language is set by the model (Gabriel's C < B with B = model bandwidth), not by the average programmer: C++-level metaprogramming, type-level computation, proofs are admissible; this is the blog's "premature passivisation" and part 8's flip. (c) The human cannot read model-scale code even when it is human-fit, so the human interface moves from reading code to reading intent and checked properties: declarations, plans with grounds, specifications, justifications; reasoners (S) substitute for reading: the human owns what is proved or checked, not what is read. This links 1.1 to Part VII (specs, SMT, Lean) as the human-ownership mechanism, not only a correctness one. (d) Nuance for the blog's "Rust skin so humans parse at speed": the skin serves spot checks and the intent layer, not full reading.

A waste of precious time. Some still strain at it; some still demand good hand coding in interviews (≥ 500 points on timed leetcode-style tasks). → Resolves chat question 3 (strength of the premise): stated as an OBSERVATION of practice dated H2 2026, with the two named exceptions; institutions (hiring) lag it.

- 2026-10-10 (Claude, derived, to confirm): premise for the chapter: the human owner is NOT assumed to know the language. Consequences: (a) the Rust surface is justified by model fluency (InD), not by human readability; humans who know Rust get spot checks as a bonus; this revises blog part 1 further than the cognitive-asymmetry nuance. The trust-chain risk moves into the open questions as mitigated, not removed.
