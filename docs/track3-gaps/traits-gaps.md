# Traits gaps surfaced by Track 3 imports

The traits/ area is a major front of Logos-vs-Rust divergence (some
deliberate, some real gaps). Batch 9 was therefore narrow.

Status legend: `Open` — not started; `Partial` — partial fix landed,
notes inline; `✅ Closed` — gap closed (commit, date).

| ID | Surface | Status | Gap | Surfaced by | Repro |
|---|---|---|---|---|---|
| T9-tr-01 | `pub fn name()` (no self) inside impl as constructor | ✅ Closed (2026-05-11) — verified that `impl T { pub fn new() -> T { … } }` (no self, no `static`) now parses and dispatches; `static fn` is no longer required. | Logos required explicit `static fn` for an associated function. | `anon-static-method` (un-trimmed) | `impl T { fn new() -> T { … } }` works |
| T9-tr-02 | mlir-gen mangled lookup for impl-on-primitive-T + generic trait method | ✅ Closed (2026-05-12) — three thin slices. (1) Sema's method-call turbofish (`x.foo::<A>()`) was being dropped on the primitive-receiver generic-method dispatch path; `user_type_args` now wins over inference there. (2) For a TypeVar receiver bounded by a trait, sema's resolution path now also auto-refs the receiver when the impl method declares `&self` / `&mut self` (the concrete-receiver path already did; the TypeVar one was unwrapping the receiver as a value, which mono substituted directly into a `&Self` slot → MLIR ptr/i64 mismatch). (3) Sema stashes the trait's type-args on the EMethodCall (so a method like `fn foo(&self) -> Option<A>` whose `A` is impl-level rather than method-level still carries the right args into mono); at mono, the sema-stashed args are dropped when the resolved impl template's `type_params` is empty — concrete-impl call sites (e.g. `impl bar<isize> for cbar`) keep their existing un-mangled symbols. | `impl<A> thing<A> for isize { fn foo(self: &isize) -> Option<A> }` — `x.foo()` was failing mlir-gen with `'pkg.isize__foo__g__ref_isize' does not reference a valid function`. | `traits/early-vtbl-resolution` (faithful — explicit turbofish at the call site since Logos has no Hindley-Milner inference-from-let-binding). | `let _x: Option<f64> = foo_func::<f64, i64>(0i64);` works |

| T9-tr-06 | HRTB syntax (`for<'a> Trait<'a, ...>` in trait bounds) | ✅ Closed (2026-05-12) — grammar admits `for<'a (, 'b)*>` binder in every `trait_bound` alt; sema discards the binder since Logos doesn't track lifetimes structurally (semantically `for<'a> Fn(&'a T)` ≡ `Fn(&T)` here). Inline bound (`F: for<'a> Foo<...>`) and where-clause (`where F: for<'a> Foo<...>`) shapes both parse. The Datalog trait engine's substitution-free design already handles the resolved bound regardless of binder presence.
