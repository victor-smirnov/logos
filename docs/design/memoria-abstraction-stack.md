# Memoria: a sketch of the abstraction stack

Status: SKETCH (2026-10-11). A first cut, expected to be redone more than once as The Logos Book's chapters on memory models and Memoria land. Feeds [ADR 0039](../adr/0039-persistent-snapshot-structures.md).

## Principle

There are many data structures and few algorithms. Each algorithm is written once, against the weakest concept it needs, as in generic programming (Stepanov: algorithms over iterator categories). A data structure is a choice of a point on each axis below, not a new body of code. Code is written per axis, never per combination.

| Axis | Varies over | Today |
|---|---|---|
| memory model | in-memory, external memory (RAM over block / KV), later distributed | in-memory only |
| node layout | block size, column packing, leaf stream shape | `NodeProfile` (one impl, `CowProfile`), `pkd` |
| branch summary | what a branch knows about a subtree: count, max key, sums, bounds | implicit: separators in `BtBranch`, counts in vectors |
| element | key and value types, fixed or Writ-encoded | generic `K`, `V`; `WritObjectData` planned (ADR 0027) |
| container kind | positional, ordered map, multimap, set, queue, index | Canon kinds `vector`, `ordered_map`; `multimap` in conuco |
| relational face | which `rel` / `op` / `order` / `size` / `unique` a structure declares | source traits, landed |
| versioning | snapshot, workspace, commit, delta | `trait Snapshot` (one store), no delta |

## Layers

Bottom to top. A layer sees only the concepts of the layer below.

1. **Memory model** (ADR 0039 D1). Levels and the edges between them; what a commit publishes and where. Not a trait in code; a description.
2. **Block placement**: allocate, resolve, release a block on a level; read and write the directory of a cut. Concept: `BlockStore` (exists: `resolve` / `alloc_block` / `release_block`, `blockptr.logos`), to become `NodeStore` and replace the `dyn_data` downcast to `MemorySnapshot` in Canon (ADR 0039 D7). CoW lives here, not in containers: a write to a block stamped by an older snapshot clones it.
3. **Node**: a bounded, relocatable unit with packed columns. Concepts: `NodeProfile` (exists), `PkdAlloc` streams. Open question O7 of ADR 0039: a node as a frozen Writ run.
4. **Tree algorithms**, generic over (node layout, branch summary): descend by a summary predicate (by position, by key, by bound), update the path, split / merge, bulk build, scan, compare two trees by shared subtrees (the delta of ADR 0039 M5). Exists in parts: `btss` / `btfl` steps, the stream-CRUD algebra (ADR 0023, `logos.mem.bt.alg`, `interp`, Canon `alg_kernel`). Missing concept: the **branch summary as a monoid**. Descent, positional access, counting and range bounds are all folds of that monoid; making it a parameter is what lets one descent serve vector, map and multimap.
5. **Container kinds**: named bundles of (layout, summary, element) with their API: `Vector` (summary: count), `OrderedMap` (summary: max key + count), `Multimap` (two-level stream), later `Set`, `Queue`, `Index`. Generated by Canon from a CFG (`CtrFamily`, `CtrClass<CFG>`); a kind adds configuration, not algorithms.
6. **Relational face**: the source declaration (`MapSource`, `OrderedMapSource`, `PositionalSource`, members `rel` / `op` / `size` / `order` / `unique`). What Deem plans against. Independent of layers 1-5: Deem never sees a node.
7. **Versioning**: `Version` / `Snapshot` / `Workspace` / `VersionStore` / `Persistent<S>` / `Versioned` (ADR 0039 D4). Orthogonal to kinds: it is a property of layer 2 (blocks are immutable once committed), exposed here; `delta_since` is layer 4's tree comparison lifted to a structure's relation.

## What this says about the current code

- The algorithms exist but are bound to concrete kinds: an ordered-map step and a multimap step (`btfl_step`) are separate hand runtimes (ADR 0023 open row). The missing parameter is the summary.
- `trait Ctr` has `size` only; `Store` is an empty marker. The vocabulary lives in `Snapshot`, which mixes layer 2 (residency pins), layer 7 (lineage) and identity. ADR 0039 D4 / D7 split it.
- Canon reaches layer 2 through a downcast, skipping the concept. Every generated family repeats it.
- `logos.lcm.deem.data` duplicated layers 3-5 without persistence (ADR 0039 D11); deleted at ADR 0039 M4b.

## Order (rough)

1. Name the summary monoid and port one descent to it (positional and keyed through one fn), with vector and ordered map as the two instances.
2. `NodeStore` over `BlockStore`; Canon families generated against it.
3. Multimap's step expressed as layer 4 over a two-level summary.
4. Layer 7 vocabulary over layer 2; `delta_since` from the shared-subtree comparison.
5. A second memory model (external memory) as a second `NodeStore`, with the store fixtures unchanged.
