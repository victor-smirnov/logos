THE FACT, AND IT IS NOT VARIANCE. B69 maps the callee's regions rigidly onto the
caller's DECLARED regions and asks the caller's graph to satisfy the substituted
pair. Rust instantiates the callee's regions at inference variables bounded from
below by the argument regions, so a bound between two regions THE CALLER CANNOT
OBSERVE is satisfied at the call point and demands nothing of the caller.

A. THE ARM IS GENUINELY TOO PERMISSIVE — the invariant half of the pin.
   regions-lifetime-bounds-fn-c            `fn a<'a,'b>(x:&mut &'a i64, y:&mut &'b i64) where 'b:'a`
   region-multiple-lifetime-bounds-on-fns-where-clause--b   the 3-region form
   Both regions sit BEHIND A `&mut` — an INVARIANT position — so they are
   rigidly the caller's regions and the caller must prove the bound, even though
   neither reaches the return type. rustc REFUSES both (twins p3, p4: "lifetime
   may not live long enough"). Reading only the RETURN TYPE is an
   UNDER-APPROXIMATION of "pinned from above", which is what the row header
   actually said and what I narrowed too far.
   ⚠ WHY MY OWN ABUSE-DIRECTION PROGRAMS MISSED IT: m01/m02 were written for
   exactly this risk (`&'b mut &'a i64` out-params) and rustc ACCEPTS both — but
   there the region ALSO occurs covariantly (`x: &'a i64`), so it stays free.
   The discriminating shape is a region occurring ONLY invariantly, and I did not
   write one. Rule 5: vary the SHAPE, not the count — seven hand programs of one
   syntax again.
   REPAIR, and it is a strict extension at the same site: `cooutretv` pins
   c_short when it occurs in the return type OR at an invariant position of any
   parameter (under a `&mut`'s pointee; a `&mut`'s OUTER lifetime stays
   covariant, which is what keeps k03/m01/m02 legal). Predictions written before
