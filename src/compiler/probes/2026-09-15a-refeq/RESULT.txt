WHAT SHOULD IT MEAN: Rust. `impl<'a, A: ?Sized + PartialEq<B>, B: ?Sized> PartialEq<&'b B> for &'a A` (and `&mut`, and the
  PartialOrd twins) compare THROUGH every reference layer; an address compare is `std::ptr::eq`. Registries searched by construct
  ("==" on references): docs/DIVERGENCES.md row "Recently caught up": `&T == &T` — now value-equality (no letter; not a blessed
  divergence); docs/spec/expressions.md `expr.binop.ref-prim-autoderef-eq` (primitive pointees only) and `expr.binop.pointer-equality`
  ("when operands are pointers (and not the deref-eligible reference-to-primitive case) compare addresses"). The second clause
  CLAIMS address equality for every non-primitive reference — false about Rust for references; it describes today's code, it does
  not canonise a divergence, so the answer is Rust's. Legality of every battery program by reading; no rustc binary on this box.
