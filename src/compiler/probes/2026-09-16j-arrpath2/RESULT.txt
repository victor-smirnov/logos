WHAT LANDED — TWO SITES, ONE FACT, AND THE SECOND IS NOT THE FORM THE PRICING RECOMMENDED

A1 "nestleaf" — SemaChecker::mark_match_scrutinee_moved, the Slice arm (sema_stmt.cpp ~9216).
  `binds_by_value` was a BOOL requiring a plain named binder (Wild with a non-`_` name), so a nested
  sub-pattern marked NOTHING and the array's scope-exit drop destroyed the moved-out leaf a second
  time. Replaced by a RECURSIVE LEAF EMITTER `emit_moved_leaves(sp, path, ty)` that emits the full
  dotted path of every leaf bound by value: Wild+named -> path; Struct -> per field (shorthand `{f}`
  binds by value, otherwise recurse); Tuple -> per index; Slice -> per index (array inside array);
  At(named) -> the whole value, else recurse; everything else emits nothing.

A2 "letidx" — SemaChecker::lower_let_pat's array path (sema_stmt.cpp ~1598).
  `mark_moved(tmp)` marked the WHOLE spill temp moved, suppressing its scope-exit drop entirely, so
  every element the pattern does not bind had no owner left. Replaced by a per-BOUND-index mark,
  `mark_moved(tmp + "." + j)`, guarded on `is_move_type(elem_t)`.

THE ORDER RESIDUAL: I INFERRED "REVERSE" FROM THREE PROGRAMS AND rustc REFUTED ME (rustorder/)
  Five armed programs now have the RIGHT destructor count and the WRONG order, which no count-based
  oracle can see. My first reading was that rustc drops a partially-moved array's remainder in reverse
  index order. Seven rustc-only probes say otherwise:
    r01/r05  fully-owned [D;3], nothing moved      123  — FORWARD, and Logos agrees. CONTROL DOES NOT MOVE.
    r03      let [y,_,_]   moved index 0           123  — remainder forward
    r04      let [_,_,y]   moved index 2           312  — remainder forward
    r02      let [_,y,_]   moved index 1           231  — the ONLY one that is not forward
    r06/r07  struct, one field moved / fully owned 123  — declaration order both ways
  So the divergence is confined to a moved index with survivors on BOTH sides, where rustc emits the
  group AFTER the moved index before the group before it. "Reverse" was wrong.
