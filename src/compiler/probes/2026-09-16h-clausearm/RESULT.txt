WHAT THE CLAUSE NOW SAYS (id unchanged, title changed):
  `region.outlives.callee-bound-checked-at-call` — Callee `where 'a: 'b` bounds
  checked at the call site only when the short side is pinned.
  The bound is enforced against the caller's DECLARED outlives graph ONLY when
  its SHORT side is PINNED FROM ABOVE: it occurs in the callee's RETURN type, or
  at an INVARIANT position of a parameter (under a `&mut` pointee, or as the
  lifetime argument of a struct/enum itself invariant in that parameter, e.g.
  `Inv<'a> { p: &'a mut &'a i64 }`). Otherwise every occurrence is covariant and
  absent from the return type, the caller may SHORTEN each argument's region,
  the callee instantiates 'a := 'b := the call point, and the bound is satisfied
  with no relation between the caller's own declared regions — so it is not
  enforced. This is Rust-canonical. The unmapped-lifetime and 'static carve-outs
  are unchanged. The pin test fails CLOSED.
  ⚠ AND IT NOW STATES ITS OWN HOLE, which the old text could not have: the pin
  test is STRUCTURAL, so a type whose invariance is a LANG-ITEM AXIOM rather
  than a structural property (`UnsafeCell`, and `Cell` over it) is not seen as
  pinning. A conformance clause that hid a known divergence from Rust would be
  the same defect this round is repairing.

⚠ A SECOND DEFECT IN THE SAME CLAUSE, FOUND WHILE EDITING IT AND NOT PREDICTED:
  its `Source:`/evidence cited `src/compiler/sema_impl.hpp#L3382-L3462`. Those
  lines today are the ATTRIBUTE-SPEC REGISTRY — `check_call_outlives` lives at
  L6888. The citation had rotted silently; spec_path_lint checks that the FILE
  exists, never the line range. Re-pointed to L6838-L7042 (the two pin helpers
  plus the checker) and to the call sites in sema_expr.cpp.
