⚠ ROW 1 — THE RECOMMENDED ARM ADMITTED AN ILLEGAL PROGRAM, AND MY OWN
  COUNTER-EXAMPLE IS WHAT CAUGHT IT
================================================================================
`cooutretv` was the arm the pricing round recommended after its own sixth column
refuted `cooutret`. Measured here, `cooutretv` AS PRICED **admits n02**, which
rustc REFUSES ("lifetime may not live long enough"). Base refuses n02 correctly,
so landing it as priced would have turned a correct refusal into an admitted
illegal program.

WHY, EXACTLY: `region_invariantly_pinned_` guards its struct arm with `if (inv)`,
and a top-level struct PARAMETER is entered with inv=false. `Inv<'b>` therefore
pins nothing, 'b is absent from the return type (i64), the pair is skipped. The
invariance is carried by the STRUCT'S OWN FIELD `&'a mut &'a i64` — not by any
`&mut` spelt in the parameter list, which is the only thing the priced arm reads.
This is the SAME defect one carrier further out than the one that refuted
`cooutret`, and the previous round's note "m01/m02 were written for exactly this
risk" is why it survived: those programs put the region at a covariant position
too, so it stayed free either way.

⚠ I PREDICTED THIS ONE FROM THE SOURCE BEFORE MEASURING IT (PREDICTIONS.txt,
written before the binary linked) and then measured it rather than acting on the
reading.

writing: a struct/enum lifetime ARGUMENT pins the region when the struct is
INVARIANT in the matching declared lifetime param — resolved with get_struct_si
and tested against the struct's own field types by the same helper. It FAILS
CLOSED: an unresolvable declaration keeps the refusal, i.e. base behaviour, so
the failure mode is over-refusal of something base already refuses, never a hole.
