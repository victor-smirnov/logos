# peg_gen_logos AST-equality oracle

A narrow tool for working on `peg_gen_logos` (the Logos-native PEG parser
generator). It checks that the parser **generated from `logos.peg` by
`peg_gen_logos` (written in Logos, emitting Logos)** produces the **same AST** as
the parser **generated by `peg_gen_cpp` (C++, embedded in `logosc`)**.

Both ASTs are Writ documents; equality is checked by serialising each to the
canonical `writ::stringify` text form and diffing byte-for-byte.

## Not part of `ctest`

This is intentionally **not** registered as a test — it rebuilds two parser
harnesses and walks the whole `tests/logos` corpus, which is only relevant when
changing the parser/codegen. Run it on demand:

```sh
tools/peg_gen_logos/oracle/run.sh [build_dir] [corpus_dir]   # defaults: build/  tests/logos/
# or, via CMake (depends on logosc + peg_gen_logos):
cmake --build build --target peg_gen_logos_oracle
```

Exit 0 + `✓ all N files: …` means every file matched. A nonzero exit lists the
mismatching files (also written to `<build>/peg_gen_logos_oracle/mismatches.txt`).

## Pieces

- `cpp_stringify.cpp` — C++ side: links the C++-generated `logos_parser`, parses a
  file, prints `writ::stringify` of the AST.
- `sdump.logos` / `oracle_main.logos` — Logos side: package `logos_parser` is
  assembled at run time (the generated `logos_parser.logos` + these), reads a file
  via raw syscalls, parses, prints the stdlib `writ.stringify`.
- `run.sh` — builds both, diffs over the corpus.

The oracle is what caught every parser divergence during bring-up (BOOL_LIT
encoding, `$...` collection, fold-mode, string/lifetime lexing, the tuple-index
`t.1.0` float split, …) and verified the packrat-memoization perf fix. Current
status: **2056/2056 (100%)** of `tests/logos` byte-identical.
